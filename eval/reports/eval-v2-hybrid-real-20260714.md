## 解读（2026-07-14，v2 人工标注集首跑）

**这是可对外引用的基线**：150 题人工标注集（`eval-set-v2.jsonl`，构建过程见
`eval/datasets/README.md`）+ 产品真实检索链（885 chunks 真实 bge-m3 向量入库，
BM25+kNN+RRF+rerank 完整混合，工具 `EvalRetrievalRunner.java`）。

1. **评估集质量决定评测有效性的实证**：同一套检索系统，在机器骨架集（v1，GT 大面积
   错位）上只有 Recall@5 = 26.4%（部-测量标志语料）/ 9.4%（BM25-only），换成人工
   标注的 v2 后达到 91.2%。此前的低分主要是评估集假阴性，不是检索能力问题。
2. **分桶结论**：data-structure 类满分（1.000）、api 类 0.963——词面实体题在混合
   检索下几乎必中；短板是 module（0.826）与 config（0.818），细看未中题多为
   语义改写幅度大的题（如"最后一次答辩在哪个教室"），是向量召回的真实边界。
3. **拒答 F1 = 0（产品端真实待办）**：25 道拒答题全部给出了结果。混合召回总能凑出
   RRF 分数 > `MIN_RRF_SCORE=0.01`，该阈值在三轮实测（BM25-only / v1 混合 / v2 混合）
   中从未拒答成功——拒答判定需要引入分数校准或相关性下限，已记录 TODOS。
4. **方法论注记（如实声明）**：GT 由锚点短语定位 + 人工复核 snippet 确认，锚点匹配
   与 BM25 同属词面机制，lexical 题（64%）的 GT 定义与 BM25 召回存在机制相关性——
   但 45 道 semantic 题（题面与 chunk 无共同措辞）Recall@5 同样高位，证明向量通路
   真实有效，整体数字不是词面自证。
5. **对比锚点**：本报告数字锚定「本科毕设语料(885 chunks) + V3 切分 + v2 评估集」。
   后续切分策略变更（如 V4）应在同一组合下重跑对比。
