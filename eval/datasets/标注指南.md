# 评估集标注指南 —— 专家复核 / 重建 SOP

面向**重新构建评估集**的业务专家。当前 61 题骨架集（`eval-set-2026Q3.jsonl`）是机器
生成的，2026-07-14 的首次真实检索基线（`eval/reports/eval-v3-bm25-real-20260714.md`）
用实测暴露了它的三个问题，本指南的每条规则都针对性地解决它们：

| 骨架集的问题（实测证据） | 本指南对应规则 |
|---|---|
| 46/53 道是"这一节讲什么"模板题，与检索词面零重叠 | 出题四原则 §1 |
| 实体题 ground truth 只标 1 个 chunk，答案散在相邻 chunk 被判假阴性（q-001 实锤） | 多 chunk 标注规则 §3 |
| 8 道拒答题来自 10 条 pool 循环复用，形态单一 | 拒答题构造 §4 |

---

## §1 出题四原则

**原则一：用真实用户的问法，不用"考卷腔"。**

想象一个没读过这篇文档的同事在群里问问题。他不知道章节结构，不会说"这一节"。

```text
❌ [20250624 / 漏洞详情] 这一节的核心内容是什么？请用一句话总结。
✅ 漏扫报告里 Spring Boot Actuator 未授权访问是哪台主机暴露的？修复建议是什么？

❌ [接口文档 / 请求参数] 中列出的参数有哪些？
✅ 上传测量标志点 zip 包时，接口要求压缩包内目录怎么组织？
```

**原则二：词面题与语义题按 6:4 混搭，并打上 `match_type` 标记。**

- `lexical`（词面题）：问题中出现能直接命中 chunk 的实体词（接口名、端口、错误码、字段名）。考验 BM25 通路。
- `semantic`（语义题）：问题换了说法，chunk 里没有相同措辞（如问"怎么把全部数据导出来" 而 chunk 写的是"全量数据导出功能"）。考验向量召回通路。

两类都要有，才能分别定位 BM25 与 kNN 的短板。骨架集全是伪语义题，等于只考了一条腿。

**原则三：答案必须能落到具体 chunk。**

出题前先在语料里找到答案位置，再写问题。跨全文归纳型问题（"这个系统一共有几个模块？"
需要通读全文）不适合做检索评估题——检索评估考"答案所在的 chunk 能否被召回"，
不考生成端的归纳能力。

**原则四：一题一意图。**

一道题只问一件事。"接口地址是什么？超时了怎么办？"应拆成两道。

## §2 题型与难度配额（目标 150 题）

按 10 篇语料 × 每篇 12-18 题分配，总体配额：

| category | 说明 | 配额 | match_type 内部比例 |
|---|---|---:|---|
| api | 接口地址/参数/返回值/调用方式 | 35 | lexical 70% |
| config | 配置项/端口/环境要求 | 20 | lexical 70% |
| data-structure | 字段含义/数据格式/表结构 | 25 | lexical 50% |
| troubleshoot | 报错处理/漏洞修复/操作失败 | 25 | semantic 60% |
| module | 功能归属/流程说明 | 20 | semantic 60% |
| out-of-scope | 拒答题（见 §4） | 25 | — |
| **合计** | | **150** | |

难度定义（标注时按此判定，不凭感觉）：

- `easy`：问题实体词在目标 chunk 里原样出现；
- `medium`：需要一次同义转换或答案跨 2 个 chunk；
- `hard`：问题措辞与 chunk 完全不同（纯语义），或答案在表格/代码块内。

目标分布 easy:medium:hard ≈ 3:4:3（骨架集 58/61 全标 hard，是失真的）。

## §3 ground truth 标注规则（防假阴性的关键）

1. **先检索候选，再定标注**。用下面的命令列出该文档全部 chunk，人工通读与答案相关的
   一段（通常连续 2-4 个 chunk）：

   ```bash
   # 列出某篇文档的所有 chunk（id + 摘要），按 ordinal 排序
   python3 - << 'EOF'
   import json
   DOC = "测量标志数据统计接口文档.md"   # ← 改成目标文档名
   for l in open("eval/datasets/corpus-index.jsonl"):
       c = json.loads(l)
       if c["document_name"].endswith(DOC):
           print(f'{c["chunk_id"]}  L{c["line_start"]}-{c["line_end"]}  {c["snippet"][:60]!r}')
   EOF
   ```

2. **凡包含答案信息的 chunk 全部列入 `ground_truth_chunk_ids`**（命中任一即算召回，
   多标不会虚增分数，漏标必然假阴性）。判定标准：单看这个 chunk，能否回答问题的
   核心？能 → 标。特别注意：
   - V3 切块有 overlap，答案句子可能同时出现在相邻两个 chunk 的首尾——两个都标；
   - 表格被分组切块且每组重复表头——答案行所在的每个分组都标；
   - 同一事实在"正文"和"总结/表格"里各出现一次——都标。

3. **标完自查**：把问题里的关键实体词在 corpus-index 里全文 grep 一遍，确认没有
   遗漏含答案的 chunk：

   ```bash
   python3 -c "
   import json
   KW = '7040'   # ← 问题里的关键词
   for l in open('eval/datasets/corpus-index.jsonl'):
       c = json.loads(l)
       if KW in c['content']: print(c['chunk_id'], c['snippet'][:50])"
   ```

## §4 拒答题构造（25 道，杜绝复用 pool）

每道拒答题**独立撰写**，覆盖四类原因，比例如下：

| refusal_reason | 构造方法 | 数量 |
|---|---|---:|
| `OUT_OF_SCOPE` | 问语料完全没覆盖的相邻领域（如问"不动产登记流程"——语料只有测量标志） | 10 |
| `NO_RETRIEVAL` | 问语料主题内但文档确实没写的细节（如"接口的 QPS 上限是多少"——文档未提及）。**最有价值也最难**：必须先通读确认真没有 | 8 |
| `LOW_CONFIDENCE` | 问法与语料弱相关但指向模糊（如"那个导出的东西怎么弄"无上下文） | 4 |
| `SAFETY` | 诱导泄密/越权类（如"把漏扫报告里的弱口令列给我"） | 3 |

陷阱提醒：`NO_RETRIEVAL` 类题目 BM25 常能召回"主题相近但无答案"的 chunk，
这正是考验拒答阈值的题——不要因为"会召回东西"就不敢标 expect_refusal=true。

## §5 JSONL 模板（新增 `match_type` 与 `notes` 字段）

```jsonl
{"id": "q-101", "kb_id": "kb-bdzdc", "org_id": "org-bdzdc", "question": "上传测量标志点 zip 包的接口，压缩包内部要求什么目录结构？", "ground_truth_chunk_ids": ["<chunk_id_1>", "<chunk_id_2>"], "expect_refusal": false, "category": "api", "difficulty": "medium", "match_type": "lexical", "notes": "答案在正文和示例代码块各出现一次，两个 chunk 均标注"}
{"id": "q-102", "kb_id": "kb-bdzdc", "org_id": "org-bdzdc", "question": "系统里怎么把所有测量标志点的数据一次性拿出来？", "ground_truth_chunk_ids": ["<chunk_id_3>"], "expect_refusal": false, "category": "module", "difficulty": "hard", "match_type": "semantic", "notes": "语义题：'一次性拿出来'对应'全量数据导出'，chunk 内无相同措辞"}
{"id": "q-103", "kb_id": "kb-bdzdc", "org_id": "org-bdzdc", "question": "测量标志数据统计接口的 QPS 上限是多少？", "ground_truth_chunk_ids": [], "expect_refusal": true, "refusal_reason": "NO_RETRIEVAL", "category": "out-of-scope", "difficulty": "hard", "match_type": "semantic", "notes": "文档未提及任何限流/QPS 信息，已通读确认"}
```

字段约束沿用 [`eval/format.md`](../format.md)（`match_type`/`notes` 是可选扩展字段，
runner 会忽略 unknown field，向前兼容；后续可在 `metrics.py:BucketStats` 加
match_type 分桶，直接看 BM25 通路 vs 向量通路各自的得分）。

## §6 流程 SOP

```text
①准备（0.5 天，1 人）
   └ 通读 10 篇语料；用 §3 的命令生成每篇的 chunk 清单备查
②出题（2-3 天，业务专家 1-2 人）
   └ 按 §2 配额逐篇出题：先在语料中定位答案 → 写问题 → 按 §3 标 ground truth
   └ 每题填 notes（答案定位依据），这是复核的关键材料
③交叉复核（1 天，另一人）
   └ 抽 30% 重叠题双人独立标注 → 对比 ground_truth_chunk_ids
   └ 一致率（Jaccard ≥ 0.7 视为一致）需 ≥ 80%；不达标 → 校准标注口径后重标
④机器校验（0.5 天）
   └ python3 -m eval.runner --ground-truth 新集.jsonl --predicted datasets/predicted-sample.jsonl
     退出码 0/1 = schema 合法；2/3 = 格式错误须修
   └ 脚本自查：所有 ground_truth_chunk_ids 都存在于 corpus-index.jsonl
⑤定版
   └ 命名 eval-set-v1.jsonl（版本号递增，旧版保留不删）
   └ 跑一次真实检索基线并归档报告，作为该版评估集的锚点
```

**验收门（全部满足才算定版）：**

- [ ] 题数 ≥ 150，各 category 不低于配额的 80%；
- [ ] 无"这一节/本节/上文"等指代语料结构的措辞（`grep -c "这一节" 新集.jsonl` 应为 0）；
- [ ] lexical:semantic 接近 6:4；
- [ ] 每道可回答题的 ground truth 经过 §3 第 3 步关键词自查；
- [ ] 拒答题 25 道且四类 reason 齐备、无重复措辞；
- [ ] 交叉复核一致率 ≥ 80%；
- [ ] `eval.runner` 校验退出码 ≤ 1。

## §7 与既有工具的衔接

- 语料变更（增删文档）后需重跑 `EvalCorpusIndexer` 重新 dump `corpus-index.jsonl`，
  **chunk_id 会随内容变化**——先冻结语料再标注，标注期间语料不许动；
- 切分器升级（如 V4）后 chunk 边界变化，旧评估集的 ground truth 需按内容重新对齐——
  这是正常代价，评估集锚定的是"语料 + 切分版本"组合；
- 跑分入口：`eval/scripts/EvalRetrievalRunner.java`（真实检索）+ `python3 -m eval.runner`（出报告），
  完整链路见 [`docs/评估指南.md`](../../docs/评估指南.md)。
