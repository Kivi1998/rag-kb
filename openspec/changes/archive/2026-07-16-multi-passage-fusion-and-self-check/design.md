## Context

现有防幻觉机制只有两层：检索阶段的 `MIN_RERANK_SCORE` 整体拒答阈值（只检查排名第一的片段），和生成阶段的 `FactVerificationGate`（`no-retrieval-fact-verification` change，只做一次粗粒度"整体有没有答案"判断）。对照"回答控制"审计后确认两处缺口需要补：多段片段的取舍/过滤、以及生成后独立于生成模型的逐句核查。完整背景与设计过程见 [brainstorming 设计文档](../../../docs/superpowers/specs/2026-07-16-multi-passage-fusion-and-self-check-design.md)。

## Goals / Non-Goals

**Goals：**
- 检索结果里的低可信片段（排名靠后但分数不达标）不再原样进入 prompt/参考来源
- Prompt 明确指示片段矛盾时的取舍原则
- 生成完成后用独立于生成模型的机制（复用现有 Reranker）核查正文是否有未支撑的断言，发现问题时追加提醒

**Non-Goals：**
- SAFETY 类拦截（用户已明确跳过）
- 不重新校准 `MIN_RERANK_SCORE` 数值本身，只扩展其应用范围
- 不做内联逐句标注，自检结果以独立提醒消息呈现
- 不专门校准自检阈值，本次先复用 0.06 做真实回归验证摸底

## Decisions

### 决策 1：低可信片段过滤复用 `MIN_RERANK_SCORE`，不发明新阈值

**选择**：`HybridRetriever.retrieveWithDecision()` 现有 `selected.get(0).finalScore() < MIN_RERANK_SCORE` 检查扩展为对 `selected` 列表里每一项都做同样的检查，不达标的过滤掉。

**理由**：这个阈值已经用 150 题人工标注集校准过，直接复用能保持"能通过拒答阈值才配被引用"这条逻辑内外一致，不需要额外的校准实验就能上线。过滤后的片段既不进 prompt 也不出现在"参考来源"卡片里，保证两者一致。

### 决策 2：自检用复用现有 Reranker 做语义核查，不引入新 LLM 调用，也不让生成模型自查自己

**选择**：新增 `AnswerSelfChecker`，用 `RerankerClient.rerank()` 给"句子 vs 它引用的资料原文"打分，低于阈值判定为不支撑；没有引用标记的实质性句子直接判定为疑似未标注断言。

**理由**：用户在澄清阶段明确要求"检查者应该独立于生成模型"——如果还是让同一个生成模型自己检查自己有没有越界，说服力有限（模型本身就倾向于自信地越界，自查时可能同样自信地觉得没问题）。相比新增一次独立 LLM 验证调用，复用已有的 Reranker 基础设施成本更低、延迟更小，且 Reranker 衡量"文本 A 与文本 B 的语义相关性"这个能力本身就适合"这句话是否真的能从这段资料里找到支撑"这个核查场景。

**已知局限**：Reranker 衡量的是语义相关性，不是严格的事实蕴含/矛盾判断——衡量"句子和资料谈的是不是一回事"比衡量"资料是否真的支持句子里的具体数值/结论"更容易；复用 `MIN_RERANK_SCORE=0.06` 这个阈值也只是起点，不代表对这个新场景是最优的。这两点都在真实回归验证里如实记录，不预设已经解决。

### 决策 3：保留实时流式输出，自检结果作为生成完成后的追加提醒，不做内联标注

**选择**：正文照常实时流式推送；生成结束（`gate.flush()` 之后）才运行自检；发现问题就追加一条 `self_check_warning` 事件，不修改已经推送的正文内容，也不在具体句子旁边加标记。

**理由**：用户明确选择"保留实时流式输出"而非"等自检完再一次性发送"，避免把现有的流式体验改造成等待体验；内联逐句标注需要精确的字符级位置映射与更复杂的前端渲染，而"事后追加一条提醒"用一个新事件类型就能实现，工程成本低很多。

### 决策 4：自检提醒不影响审计状态，不写入会话记忆

**选择**：`QueryController` 的审计状态判断保持不变（`self_check_warning` 不是新的审计状态，本轮仍按 `found:true`/`found:false` 判 `COMPLETED`/`REFUSED`）；`ConversationMemoryOrchestrator.recordTurn()` 写入的 answer 文本不包含自检提醒。

**理由**：这是设计自查阶段主动补的澄清，避免重蹈上次 `no-retrieval-fact-verification` 实现中途才发现审计字段遗漏的覆辙——自检提醒是附加的质量信号，不是拒答，混进审计状态或会话记忆都会造成语义混乱。

## Risks / Trade-offs

- **[Risk] `MIN_RERANK_SCORE=0.06` 未必适合"句子-资料语义支撑度"这个新场景** → Mitigation：真实回归验证会摸出实际命中率/误伤率；如果效果不理想，需要单独校准新阈值，不假定复用就一定有效
- **[Risk] 句子切分与"过渡句"判定（长度 ≥ 6 字）是启发式规则** → Mitigation：先用简单规则跑真实数据看效果，误伤率高的话再调整规则，不追求一次到位
- **[Risk] 自检增加生成完成后的额外延迟（若干次 Reranker 调用）** → Mitigation：不阻塞已展示的正文，只是提醒消息的时间差；Reranker 调用异常时 fail-open，不发送提醒也不影响主流程
- **[Risk] 前端遗漏处理新事件类型会导致提醒静默失效**（不报错，但没有任何提示） → Mitigation：任务清单包含前端改动与真实浏览器验证
