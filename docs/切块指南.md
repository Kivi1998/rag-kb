# 切块指南 —— V3 结构感知五招式

本文是 rag-kb「文档切块」环节的**权威入口文档**。解析环节见 [解析指南](解析指南.md)，
评估环节见 [评估指南](评估指南.md)。

`TechnicalChunker`（`backend-py/app/ragcore/chunk/technical_chunker.py`，Java 时代原实现
在 `backend/.../ragcore/chunk/impl/`，随 Java 退役已删除并 1:1 移植到 Python）在 2026-07-14
完成 V3 升级（PR #13），实现五项结构感知技术：

| # | 招式 | 实现 |
|---|---|---|
| 1 | 多风格文档层级识别 | `HeadingStyle` 枚举：CN_FORMAL（编/部分→章→节→条→(一)）、CN_NUMERIC（1./1.1/1.1.1）、CN_INFORMAL、EN 四套模式组，`detectDominant()` 按命中数自动选主风格，未命中则优雅降级 |
| 2 | 递归多级级联切分 | 超长结构单元按 结构层级 → 空行段落 → 句子(+overlap) 三级递归降级（`recursiveSplit`），任何一级失败自动降到下一级 |
| 3 | 表格专用切块 | `chunkTableSection`：大表格按行分组，**每组重复表头**，保证跨 chunk 检索时表头语境不丢；仅超长表头无数据行时也不丢块 |
| 4 | 智能重叠 | overlap 起点对齐句子边界（不从半句开始），默认 160/1200 ≈ 13% 比例，已由回归测试锁定 |
| 5 | 丰富 chunk 元数据 | `enrichMetadata()` 写入 `sectionPath` / `contentType` / `isKeyClause` / `prevChunkId` / `nextChunkId`；因 ES 索引对 `metadata` 做 `dynamic:true` 透传，**零 schema / 索引代码改动** |

**明确不在 V3 范围内**（记录于 `TODOS.md`）：ML 分类器兜底（层级识别目前纯规则）、检索侧对 prevChunkId/nextChunkId 的消费（上下文扩展）。

## 切块行为快速验证

```bash
cd backend-py
uv run pytest tests/ragcore/chunk/test_technical_chunker.py -v
```

`eval/fixtures/v3-chunks-main.json`（5 个代表性文档：表格/法律条款/清单/代码/混排的块数、块大小分布、
元数据覆盖统计）是 Java 时代 `TechnicalChunkerTest#generateEvalFixture` 生成的历史快照，随 Java 退役
该生成方式已不存在；Python 移植版明确不重建这套逐块精确对齐的黄金基准生成流程（见
`backend-py/tests/ragcore/chunk/test_technical_chunker.py` 顶部说明），改为单元级断言（heading path、
overlap 边界、content hash 等），fixture 文件本身作为历史效果记录保留，不再随代码变更更新。

已验证的典型效果：法律条款文本从 V0 的粗粒度切分变为按「第 X 条」逐条切分（实测 8 块，prev/next 链接完整）。
