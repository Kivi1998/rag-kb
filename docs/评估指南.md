## 方法论

> 业内共识：**没有评估集的切分优化都是自嗨。**

量化切分质量的标准做法是构造 QA 评估集跑检索召回：

1. 选一批代表性文档；
2. 人工出题 + 标注 ground-truth chunk（答案应来自哪个 chunk）；
3. 用当前切分方案建库，对每题检索 top-k，看 ground-truth 是否被找到；
4. 换切分策略重复跑，横向对比。

核心指标（由 `eval/metrics.py` 计算）：

- **Recall@k**：可回答题中，前 k 个检索结果命中任一 ground-truth chunk 的题目占比——最直接反映切分是否合理；
- **MRR**：答案 chunk 首次命中排名的倒数平均——反映排序质量；
- **拒答精确率/召回率/F1**：期望拒答题（无依据/越界）是否被正确拒答。

## 完整评测工作流

```bash
# ① 语料预处理（仅 XLSX / 含图 DOCX 需要）
python3 eval/scripts/xlsx_to_md.py in.xlsx out.md
python3 eval/scripts/docx_to_md.py in.docx out.md

# ② dump corpus 索引（真实跑 V3 解析+切块，调用 backend-py 生产类）
python3 eval/scripts/eval_corpus_indexer.py eval/datasets/corpus/<主题> eval/datasets/corpus-index.jsonl

# ③ 生成 QA 骨架 → 业务专家复核标注
python3 eval/scripts/build_qa_set.py

# ④ 生成检索预测
#    mock 模式：predicted = ground truth，仅验证 pipeline（指标恒为 100%，无评测意义）
python3 eval/scripts/generate-predictions.py --mode mock --output eval/predictions/xxx.jsonl
#    api 模式：调后端真实检索（前置条件见下方「真实评测待办」）
python3 eval/scripts/generate-predictions.py --mode api --api-url http://localhost:8080 ...

# ⑤ 出报告
python3 -m eval.runner \
  --ground-truth eval/datasets/eval-set-2026Q3.jsonl \
  --predicted    eval/predictions/xxx.jsonl \
  --meta chunker=technical-chunker@v3 \
  --output-md eval/reports/eval-xxx.md
```

一键跑 mock 全流程：`bash eval/run-quick-eval.sh`。

**基线跑法**（复现）：`eval/scripts/eval_retrieval_runner.py`（Python，调用 backend-py
生产类，已取代同名 Java 工具）—— 把 `corpus-index.jsonl` 的 885 个 V3 真实切块连同
真实 bge-m3 向量经产品 `ElasticsearchChunkIndex` 写入独立评测索引
`rag_chunks_eval_v3`，再逐题调用产品 `HybridRetriever`（BM25+kNN+RRF+rerank，含拒答
阈值门槛）。chunk_id 与 ground truth 同源，无映射误差。命令见该文件头部 docstring 与
datasets/README。

**核心实证**：同一套检索系统，在机器骨架集上 Recall@5 仅 26.4%，换成人工标注 v2 集后
91.2%——评估集质量决定评测有效性；此前的低分是评估集假阴性，不是检索能力问题。
详细解读（含分桶短板与方法论注记）见 v2 报告尾部。

**拒答阈值校准是一次诚实的首轮修复**：把三轮实测均为 0 的拒答 F1 提升到 0.564，
代价是 3/125 应答题被误伤（Recall@5/MRR 各降 0.008）。收益集中在"检索真找不到
相关内容"这一类拒答；NO_RETRIEVAL（主题相关但事实缺失）与 SAFETY（内容合规）
类拒答需要独立机制，非本次范围。

**后续评测待办**（按预期收益排序）：

1. **NO_RETRIEVAL 类拒答方案**：需要生成阶段的事实核验（检索到的 chunk 是否真的
   陈述了被问及的具体数值/事实），而非检索相关性判断；
2. **SAFETY 类拒答方案**：需要独立的内容安全/合规分类器，与检索相关性正交；
3. 业务专家对 v2 做一轮独立盲标复核（30% 抽样、Jaccard ≥ 0.8），补齐验收门 6 的严格形态（当前为 AI 单标注人+锚点复核）；
4. ES 加中文分析器（IK / smartcn）+ heading_path 参与 BM25 召回，观察 module/config 短板类（Recall@5 0.77-0.83）能否抬升；
5. 检出 `1fc29ab`（V0 切分）在同一 v2 集组合下重跑，得到切分策略的真实对比。
