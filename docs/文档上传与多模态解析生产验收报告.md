# 文档上传与多模态解析生产验收报告

## 1. 验收结论

截至 2026-07-13，文档上传与多模态解析模块达到生产代码验收基线，并通过本机生产同构的 5000 份全链路验收。

本结论覆盖：上传会话、MinIO 直传、服务端完整性校验、异步任务、多 Worker 租约、解析、OCR、ASR、结构化切块、Embedding 协议容错、解析产物持久化和 Elasticsearch 写入。

本结论不覆盖：真实 Embedding 模型的召回质量、Rerank/Generation、日均 5000 次问答容量、生产网络 TLS/CORS、真实公司长文档容量分布和 24 小时稳定性。

## 2. 验收环境与链路

```text
HTTP initiate
  → MinIO presigned PUT
  → complete 两阶段完整性校验
  → PostgreSQL ingestion_job
  → 双 Worker 领取/心跳/租约接管
  → Java Parser 或多模态 Parser Gateway
  → 版本化解析产物写回 MinIO
  → 结构化切块
  → Embedding 兼容协议
  → Elasticsearch Bulk Upsert
  → READY
```

真实依赖包括 PostgreSQL 16、Redis 7、MinIO、Elasticsearch 8.13.4、双 Java Worker、RapidOCR 和 Faster Whisper。Embedding 使用确定性协议替身，并主动注入前两次 HTTP 503，用来签收客户端容错，不用于签收检索质量。

## 5. 故障注入结果

### 5.1 Worker 中断

在 `worker-a` 正处理两份扫描 PDF 时执行强制停止。租约到期后，`worker-b` 分别于 `2026-07-13T16:25:46.851Z` 和 `2026-07-13T16:25:48.158Z` 恢复两个任务。两任务 `attempt` 从 1 增加为 2，最终均为 `READY`。

这证明：数据库租约恢复实际生效；`attempt + leaseOwner + leaseExpiresAt` fencing 能阻止旧 Worker 在租约失效后推进任务状态。

### 5.2 Embedding 瞬时故障

模型协议替身的前两次 `/v1/embeddings` 请求强制返回 503，第三次开始返回 200。最终 5000 份文档 0 失败，证明连接异常、HTTP 429 和 5xx 的有界重试链路生效。参数类 4xx 不进入重试，避免无意义放大故障。

### 5.3 资源安全

验收结束时所有服务均无 OOM、无非预期容器重启。Parser Gateway、后端和辅助服务采用非 root、只读根文件系统或最小权限配置；Parser 在接收请求体前先获取并发槽，并限制文件名、Content-Length、流式实际字节数和临时目录容量。

## 6. 关键生产修复

| 问题 | 修复 |
|---|---|
| 大文件 complete 持有数据库行锁读取整个对象 | 改为短事务领取 verification token，对象读取在事务外完成，token fencing 后短事务提交 |
| complete 进程崩溃后会话永久卡住 | V011 增加校验租约字段，定时恢复过期 VERIFYING 会话 |
| 旧 Worker 租约失效后仍可能推进状态 | 所有阶段推进、产物记录、失败回写和心跳均校验 attempt、owner 与 expiry |
| Worker 条件装配顺序导致生产容器不消费任务 | 移除不可靠的 `ConditionalOnBean`，开启 Worker 时缺少 Pipeline 直接 fail-fast |
| Embedding 短暂断连直接令文档 FAILED | 增加可配置的有界瞬时故障重试 |
| DOCX 截图内容被静默忽略 | 检测内嵌图片后路由多模态网关，抽取正文/表格并对图片 OCR |
| Parser 并发限制在文件落盘之后 | 在读取请求体之前获取信号量，并校验声明与实际大小 |
| OCR/ASR 进程启动但模型未就绪 | `/ready` 同时检查 OCR 与 ASR，可配置启动预加载和强制就绪 |
| 指标端点裸露 | `/metrics` 使用独立密钥和常量时间比较，指标标签集合有界 |

## 7. 生产发布门禁

以下事项属于环境发布门禁，不阻断本次代码验收，但上线前必须完成：

1. 使用公司真实文档的脱敏样本，按文件大小、页数、扫描分辨率、代码块密度和音视频时长分层复验。
2. 在目标网络验证浏览器到对象存储的 TLS、CORS、DNS、弱网重试和超大文件限制。
3. 接入生产密钥管理、Prometheus、日志平台和告警路由，不使用验收环境凭证。
4. 按目标 CPU/GPU 资源执行至少 24 小时稳定性和积压恢复测试。
5. 对旧版 `.doc/.ppt` 明确采用上传前转换服务或拒绝策略；当前原生验收格式是 `.docx/.pptx`。
6. 日均 5000 次查询属于检索与问答阶段，必须另做真实 Embedding、Rerank、Generation、召回质量和并发容量验收。
