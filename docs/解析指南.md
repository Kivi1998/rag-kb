# 解析指南

本文是 rag-kb「文档解析」环节的**权威入口文档**：当前实现与能力边界、相关详细文档索引。
切块环节见 [切块指南](切块指南.md)，评估环节见 [评估指南](评估指南.md)。

链路全景中的位置：

```text
上传 → 【解析（DocumentParserFactory + deepdoc 本地 OCR/ASR）】
     → 切块（TechnicalChunker V3，结构感知）
     → 索引（Elasticsearch BM25 + 默认 kNN；可选 Milvus ANN，chunk metadata 由 ES 透传）
     → 检索问答（RRF + Rerank + SSE）
     → 评估（eval/ 离线评测：Recall@k / MRR / 拒答 F1）
```

## 当前实现

- **backend-py `DocumentParserFactory`**：Markdown、代码、JSON/YAML/XML、DOCX、PPTX、文本
  PDF、字幕等本地直接解析；
- **`LocalMultimodalDocumentParser`**（`app/ragcore/parser/local_multimodal_parser.py`）：
  扫描 PDF / 图片走 OCR，音视频走 ASR，DOCX/PPTX 内嵌图片走逐图 OCR 兜底——原来是独立
  `parser-gateway` 微服务通过 HTTP 调用（Java 后端时代的架构，Java 没有好用的 OCR/ASR
  生态），backend-py 本身就是 Python 后不再需要跨进程调用，已把这块能力直接合并为进程内
  模块调用,parser-gateway 已下线删除；
- **deepdoc 集成**（移植自 RAGFlow deepdoc，Apache 2.0，许可证见
  `backend-py/app/ragcore/parser/deepdoc/LICENSE_THIRD_PARTY`）：
  - **版面分析**（LayoutRecognizer）：解决多栏扫描文档被按行交叉拼接的问题；
  - **表格结构识别**（TSR + R/C 标注算法）：解决无边框表格行列错配的问题。

Java 后端(`backend/`)仍保留原有的 `parser.multimodal` HTTP 客户端配置(默认关闭)，但
不再迁移到可用状态——Java 已在退役路上，这项能力的后续维护只在 backend-py 一侧进行。

## 已知限制（详见 `TODOS.md` 的 deepdoc 后续项）

- 文本型 PDF（无需 OCR 的多栏 PDF）仍走 PyMuPDF 原生提取，多栏交叉问题未修；
- 印章压字无解决方案（四个参考项目均未解决）；
- deepdoc 效果仅用合成图片验证过，真实扫描件样本待验收；
- XLSX 与含图 DOCX 不被 `DocumentParserFactory` 支持，评估语料需先用
  `eval/scripts/xlsx_to_md.py` / `docx_to_md.py` 预处理（见 [评估指南](评估指南.md)）。

## 部署

不再需要独立部署步骤——`LocalMultimodalDocumentParser` 是 backend-py 进程内的一个模块，
随主服务启动、随主服务的依赖（`pyproject.toml`）安装，模型文件（ONNX/huqie 词典）随代码
一起分发。开关只有一个环境变量：`RAG_MULTIMODAL_PARSER_ENABLED`（`backend-py/.env`）。
