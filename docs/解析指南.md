# 解析指南

本文是 rag-kb「文档解析」环节的**权威入口文档**：当前实现与能力边界、Parser Gateway
独立部署步骤、相关详细文档索引。切块环节见 [切块指南](切块指南.md)，评估环节见
[评估指南](评估指南.md)。

链路全景中的位置：

```text
上传 → 【解析（backend Parser + parser-gateway/deepdoc）】
     → 切块（TechnicalChunker V3，结构感知）
     → 索引（Elasticsearch BM25 + kNN，chunk metadata dynamic 透传）
     → 检索问答（RRF + Rerank + SSE）
     → 评估（eval/ 离线评测：Recall@k / MRR / 拒答 F1）
```

## 当前实现

- **backend `DocumentParserFactory`**：Markdown、代码、JSON/YAML/XML、DOCX、PPTX、文本 PDF、字幕等直接在 Java 侧解析；
- **parser-gateway（Python）**：扫描 PDF / 图片走 OCR，音视频走 ASR；
- **deepdoc 集成**（移植自 RAGFlow deepdoc，Apache 2.0，见 `parser-gateway/app/deepdoc/LICENSE_THIRD_PARTY`）：
  - **版面分析**（LayoutRecognizer）：解决多栏扫描文档被按行交叉拼接的问题；
  - **表格结构识别**（TSR + R/C 标注算法）：解决无边框表格行列错配的问题。

## 已知限制（详见 `TODOS.md` 的 deepdoc 后续项）

- 文本型 PDF（无需 OCR 的多栏 PDF）仍走 PyMuPDF 原生提取，多栏交叉问题未修；
- 印章压字无解决方案（四个参考项目均未解决）；
- deepdoc 效果仅用合成图片验证过，真实扫描件样本待验收；
- XLSX 与含图 DOCX 不被 `DocumentParserFactory` 支持，评估语料需先用
  `eval/scripts/xlsx_to_md.py` / `docx_to_md.py` 预处理（见 [评估指南](评估指南.md)）。

## Parser Gateway 独立部署

```bash
cd parser-gateway
cp .env.example .env
# 使用密钥管理系统写入 PARSER_API_KEY，不要把真实 .env 提交到 Git。
# ASR 验收必须显式确认下列基线；任一命令无输出即停止部署。
grep -E '^PARSER_PRELOAD_WHISPER=true$' .env
grep -E '^PARSER_REQUIRE_ASR_READY=true$' .env
grep -E '^PARSER_WHISPER_MODEL=small$' .env
grep -E '^PARSER_WHISPER_DEVICE=cpu$' .env
grep -E '^PARSER_WHISPER_COMPUTE_TYPE=int8$' .env
docker compose -f compose.production.yml config --quiet
docker compose -f compose.production.yml build --pull
docker compose -f compose.production.yml up -d
docker compose -f compose.production.yml ps
docker compose -f compose.production.yml logs --tail=200 parser-gateway

curl -fsS http://127.0.0.1:8081/ready
docker compose -f compose.production.yml exec parser-gateway id
```

验收预期：`/ready` 返回 `{"status":"UP","asrLoaded":true}`，`id` 显示 uid `10001`。网关使用只读根文件系统、`/tmp` tmpfs、持久化模型缓存卷、能力删除与资源上限。

生产需根据实际文档规模设置 `PARSER_MAX_FILE_BYTES`、`PARSER_MAX_CONCURRENCY`、`PARSER_TMPFS_SIZE`、CPU/内存上限和 Whisper 模型。CPU 环境建议从 `small + int8 + concurrency=2` 起步；启用 GPU 前需另外制作带 CUDA 的锁定版本镜像。后端的 `RAG_MULTIMODAL_PARSER_API_KEY` 必须与 `PARSER_API_KEY` 完全一致。

标准宿主机端口统一为 `8081`：本机部署时后端端点为 `http://127.0.0.1:8081/v1/parse`；同一 Docker 网络中使用 `http://parser-gateway:8081/v1/parse`。升级时必须用不可变镜像标签/摘要；回滚时恢复上一镜像标签并重新 `up -d`，模型缓存卷不删除。
