# 检索召回·混合检索指南

本文说明 rag-kb 混合检索环节的实现结构、关键参数与实验数字来源。

## 实现结构

```text
用户问题（经指代消解，见 Query理解与改写现状.md）
  └─ HybridRetriever（编排，只依赖端口接口，不直接依赖数据库 SDK）
       ├─ LexicalCandidateSource：ES BM25 召回（实现：ElasticsearchLexicalCandidateSource）
       ├─ VectorCandidateSource：向量召回，按 rag.vector.provider 切流（见下）
       │    └─ ChunkHydrator：Milvus 命中回查 ES 补齐正文，二次校验 org/kb 边界
       ├─ RrfFusion：倒数排名融合，默认等权；可由查询意图调整两路权重
       ├─ 可选 Rerank（见 重排与检索优化指南.md）
       └─ 拒答判定（MIN_RERANK_SCORE 门槛，见 重排与检索优化指南.md）
```

- **代码**：`HybridRetriever.java` / `LexicalCandidateSource`/`VectorCandidateSource`/
  `ChunkHydrator`（端口接口）/ `ElasticsearchLexicalCandidateSource.java`（BM25 实现）/
  `RrfFusion.java` / `ElasticsearchChunkIndex.java`（`rag_chunks_v1` mapping 与 Bulk
  Upsert）/ `RetrievalOptions.java`（均在 `backend/.../ragcore/retrieval|index/`）；
- **BM25 侧字段加权**：`symbol_names` / `config_keys` / `error_codes` 等技术标识字段
  7-8 倍权重，保证类名/错误码/配置 key 这类必须逐字精确的查询优先走关键词精确召回
  （这也是 Query Rewrite 保持关闭的原因，见[总体架构](architecture.md)决策 3）；
- **多租户隔离**：ES 查询由服务端强制注入 `org_id`/`kb_id` 过滤，跨组织按资源不存在
  处理（[总体架构](architecture.md)决策 4，自动化测试为发布门禁）；Milvus 路径同样强制
  服务端参数化过滤，命中后经 ES 回查二次校验（见下）。

## 向量检索：Milvus 切流（2026-07-18 新增）

原来 ES 同时承担 BM25 与向量 kNN；向量检索现在可以独立切到 Milvus，由服务端配置
`rag.vector.provider` 决定，外部问答 API 不感知、不接受请求覆盖：

| 模式 | 行为 |
|---|---|
| `elasticsearch`（默认） | 现有 ES kNN，本文其余部分描述的行为不变 |
| `shadow` | 线上仍返回 ES kNN 结果，同时采样查询 Milvus，只记录 TopK 重合率/差异数/延迟指标，不影响用户可见结果 |
| `milvus` | Milvus 为主向量候选源，超时/故障自动回退 ES kNN，再失败退化为纯 BM25 |

- **ES 与 Milvus 分工**：ES 仍是唯一的正文与引用定位权威源；Milvus 只保存向量与最小过滤
  字段（`chunk_id`/`org_id`/`kb_id`/`document_id`/`retrieval_ready`），Milvus 命中的
  `chunk_id` 必须回 ES 批量补齐正文，缺失/越界的 ID 直接丢弃并计入孤儿指标；
- **可见性闸门**：摄取双写走"ES 暂存→Milvus 暂存→Milvus 激活→ES 最终激活"，只有最后一步
  ES 激活成功文档才进 `READY`；所有查询路径统一过滤 `retrieval_ready=true`，中间步骤失败
  不会有暂存数据被检索到；
- **完整决策与迁移计划**：见[总体架构](architecture.md)决策 12、[Milvus 向量检索迁移设计](Milvus向量检索迁移设计.md)；D1-D7 原始决策保存在对应 OpenSpec 归档中；
- **已知限制**：历史数据回填 Milvus、真实环境集成验收、150 题 ES/Milvus 对比评测、目标
  并发压测均未做，默认配置仍是纯 ES 模式，详见 `TODOS.md`。

## 关键参数与数字来源

| 参数/数字 | 值 | 怎么来的 |
|---|---|---|
| 生产默认候选池 `candidateLimit` | 50 | 2026-07-15 用 150 题 v2 评估集实测 N∈{10,20,30,50}：N 降到 10 时 Recall@5 掉 5.6 个百分点、只换回约 430ms（median），性价比不划算，**默认 50 不下调**。报告 `eval/reports/candidate-pool-size-tuning-20260715.md` |
| 最终保留 `resultLimit` | 8 | 进生成 prompt / 作为引用来源的片段上限 |
| RRF `rank_constant` | 60 | 业界常用默认值，代码中保持固定 |
| 默认 BM25/向量权重 | `1.0/1.0` | 未启用意图分类或分类失败时保持原始等权行为 |
| 精确检索型权重 | `1.3/0.7` | 已实现、默认关闭、未经真实评估集验证；优先技术标识的 BM25 召回 |
| 语义型权重 | `0.7/1.3` | 已实现、默认关闭、未经真实评估集验证；提高语义向量候选的融合贡献 |
| **权威基线 Recall@1/5/10 = 0.816/0.904/0.912，MRR = 0.849** | — | 150 题人工标注 v2 评估集 × 本页完整链路（含拒答门槛）实测，报告 `eval/reports/eval-v2-calibrated-20260714.md`；评测方法论与"机器骨架集 26.4% vs 人工标注集 91.2%"的实证见[评估指南](评估指南.md) |

## 降级行为

- Embedding 不可用 → BM25-only（见 [Embedding指南](Embedding指南.md)）；
- Rerank 不可用 → 直接返回 RRF 排序结果（见[重排与检索优化指南](重排与检索优化指南.md)）；
- 两类降级都写入审计标记（`embedding_fallback`/`rerank_fallback`）并告警。
